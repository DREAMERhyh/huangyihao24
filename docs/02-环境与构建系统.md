# 02 环境与构建系统

> 目标：看懂 `make` 每个 target 背后实际发生了什么、`build/` 里每个文件是谁用的。
> 全程在 `Project1` 分支、QEMU 为目标（无开发板）。

## 1. 环境清单

| 组件 | 路径 | 作用 |
|---|---|---|
| 交叉工具链 | `riscv64-unknown-linux-gnu-{gcc,objdump,readelf,nm,gdb}` | 编出 RISC-V 目标代码 |
| QEMU | `~/OSLab-RISC-V/qemu/riscv64-softmmu/qemu-system-riscv64` | 模拟器（`make run`） |

## 2. 每条命令背后发生了什么

```bash
make dirs        # 只是 mkdir -p ./build
```

```bash
make elf         # 交叉编译三件事：
                 # ① bootblock：gcc bootblock.S 仅汇编，-e main 入口，TEXT_START=0x50200000
                 # ② 内核 main：head.S + init/main.c + bios/common.c + kernel/loader/*.c + libs/string.c，
                 #    TEXT_START=0x50201000
                 # ③ crt0.o 编一次；4 个 app 各链接一次（crt0.o + test/test_project1/<app>.c），
                 #    TEXT_START 逐个自增 0x10000（见 Makefile 的 $(eval) 技巧）
```

```bash
make image       # ① 用宿主机 gcc 编 tools/createimage.c → build/createimage
                 # ② cd build && ./createimage --extended bootblock main 2048 auipc bss data
                 #    产出 kernel.img（bootblock+内核+AppInfo）与 apps.img（各 app）
                 # ③ cd build && cat kernel.img apps.img > image   ← 任务5 的"拼接"
```

```bash
make run         # 启动 QEMU：
                 #   qemu-system-riscv64 -nographic -machine virt -m 256M
                 #     -kernel ~/OSLab-RISC-V/u-boot/u-boot -bios none
                 #     -drive if=none,format=raw,id=image,file=build/image
                 #     -device virtio-blk-device,drive=image
                 #     -monitor telnet::45454,server,nowait -serial mon:stdio
                 # 启动后等约 6 秒，出现 "=> " 后输入 loadboot
make debug       # 同上，另加 -s -S（停在第一条指令，监听 TCP:1234，等 gdb）
make gdb         # gdb build/main -ex "target remote:1234"  （配合 make debug）
make floppy      # 真硬件写盘（方案 A）：dd if=build/image of=/dev/sdX3
make asm         # 对 bootblock/main/各 app 做 objdump -d，输出 * .txt 到仓库根目录
```

> 注意 `make image` 的依赖铁律：**任务 3 之前禁止执行 `make image` / `make all`**——
> 那时自建 createimage 的 `write_img_info()` 还是空的，产出的镜像没有信息字段，
> bootblock 读不到内核扇区数。任务 1/2 一律用手工官方 createimage：
> `cd build && ../createimage --extended bootblock main`。

## 3. build/ 每个产物是谁用的

| 产物 | 是谁编译的 | 谁在运行/使用 | 备注 |
|---|---|---|---|
| `bootblock` | Makefile（仅汇编 `-e main`） | 镜像扇区 0 → 内存 0x50200000 | ELF；createimage 只取 PT_LOAD 内容 |
| `main` | Makefile（内核全部源） | 镜像扇区 1..K → 0x50201000 | head.S 入口；BSS 运行时清零 |
| `crt0.o` | Makefile（crt0.S 编一次） | **被 4 个 app 链接**，不是独立产物 | 共享：`_start` 进每 app |
| `2048/auipc/bss/data` | Makefile（crt0.o + 各自 .c） | apps.img 里，按名加载到 0x52000000+i*0x10000 | 入口 = 窗口基址 |
| `createimage` | 宿主机 gcc（tools/createimage.c） | **构建期**工具，不随镜像运行 | 产出 kernel.img/apps.img |
| `kernel.img` | createimage | 磁盘扇区 0..1+K+A-1；启动期被读 | bootblock+内核+AppInfo |
| `apps.img` | createimage | 磁盘扇区 1+K+A..；运行 app 时才被读 | 各 app 紧凑 |
| `image` | Makefile `cat` | QEMU `-drive` 挂的整块磁盘 | = kernel.img ∥ apps.img |

## 4. 编译选项怎么读

```
CFLAGS = -O2 -std=gnu11 -fno-builtin -nostdlib -nostdinc -Wall -mcmodel=medany -ggdb3
```

- `-O2`：开启优化。**start-code 自带**，不是任务 4 "加"进去的——任务 4 只是确认生效，
  没有可对比的基线版本（见 `log/task4-工作日志.md` §7）。
- `-mcmodel=medany`：代码地址不依赖具体链接位置（"任何位置都行"），这允许我们为
  不同产物传不同的 `TEXT_START`。
- `-nostdlib -nostdinc`：不用标准库——这就是为什么打印要自己调 BIOS、字符串函数
  在 `libs/string.c` 里手写。
- `-Wl,--defsym=TEXT_START=… -T riscv.lds`：把入口地址注入链接脚本。

## 5. 常见坑（环境层）

- 官方 `./createimage` 是只读权威二进制，**不许删/改/覆盖**；它 git 权限 644，
  需要执行时先 `chmod +x`，提交前还原 644。
- shell 工作目录在多次调用间**会保留**：执行过 `cd build` 后，后续命令都相对 build/
  ——建议每条命令带绝对路径或先 `cd` 回仓库根。
- `--extended` 是两个减号（Makefile 里 `image` 已自带；手工跑官方时要自己写）。
