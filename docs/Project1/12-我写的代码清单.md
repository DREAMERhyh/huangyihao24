## 1. 任务 1：bootblock 打印标志串

**我做了什么（一句话）**：在 bootblock 的 `[p1-task1]` 处填入三行汇编，让开机后第一个执行的程序
借用 BIOS 在屏幕上打印一句标志串。

**设计要点**：
1. **用 `call`（即 `jal`）而不是 `j`**——`0x50150000` 处是一条 `ecall` + 一条 `ret`，
   `ret` 靠 `ra` 返回；`call` 会自动把返回地址填进 `ra`，用 `j` 则返回地址是垃圾值，必然跑飞。
2. **参数约定**：字符串地址放 `a0`、功能号放 `a7`（`BIOS_PUTSTR = 9`）。
3. **结尾保留 `j stop` 自旋**，防止执行流"掉进"后面的 `.data` 数据区被当成指令执行。

## 2. 任务 2：加载内核 + C 运行环境 + 键盘回显

**我做了什么（一句话）**：让 bootblock 从 SD 卡把内核搬进内存并跳过去；让内核入口 `head.S`
把 C 语言需要的环境搭好（清 BSS、架栈）；让内核第一次能和键盘交互。

**三块改动**：

### ① bootblock.S：读内核
**设计要点**：
- 内核占几个扇区**不写死**，从镜像偏移 `0x1fc` 用 `lh` 读（createimage 刻的）；
- `lh` 不能拿绝对地址直接当基址（汇编器报 illegal operands），必须先 `li` 进 `t3` 再 `0(t3)` 读；
- 逐扇区循环读，代码不绑定扇区数（内核变大变小都不用改）；
- `t0/t1/t2` 分别是"当前扇区号 / 目标地址 / 剩余扇区数"，`a0/a1/a2/a7` 交给 BIOS 调用。

### ② head.S：清 BSS + 架栈
**设计要点**：
- 清 BSS 用 `__bss_start` / `__BSS_END__` **符号取边界**（链接脚本生成），不硬编码地址；
- 栈顶 `0x50500000`（`KERNEL_STACK` 宏），16 字节对齐，向下生长；
- 最后 `call main` 才真正进入 C 世界。

### ③ main.c：键盘回显
**设计要点**：
- **`bios_getchar()` 无输入时返回 `-1`，必须跳过**，否则会把 `0xFF` 打进屏幕造成乱码；
- 删掉了原始骨架里 `while(1){ wfi; }` 的"睡死"循环（我的改动让它变成不可达死代码）。

## 3. 任务 3：自建 createimage + 按 taskid 加载用户程序

**我做了什么（一句话）**：自己写打包工具（把布局从"官方黑盒"变成"我们说了算"）；
给用户程序设计 C 运行环境与"返回内核"机制；让内核能按编号加载并执行用户程序。

**五块改动**：

### ① tools/createimage.c：自建打包
- 新增 3 个宏：`KERNEL_FIXED_SECTORS=32`、`APP_FIXED_SECTORS=15`、`IMG_APP_NUM_LOC=0x1f8`；
- padding 逻辑改为"固定扇区分配"：bootblock 补 1 格、内核补 32 格、每个 app 补 15 格；
- 打印"实际/分配"对照表；**实际 > 分配就 `error()` 退出**（宁可打包失败也不产出坏镜像）；
- 实现 `write_img_info()`：往 `0x1fc` 写内核实际扇区数、`0x1f8` 写 app 数目、`0x1fe` 写 `55 aa` 签名。

### ② kernel/loader/loader.c：按编号加载
- 两个公式：`entry = TASK_MEM_BASE + taskid*TASK_SIZE`（**内存**地址=搬到哪）、
  `block = 1 + 32 + taskid*15`（**磁盘**扇区号=从哪搬）；
- 一次读满 15 格（padding 全是 0，顺便把窗口刷干净）；
- 用 `0` 当失败哨兵（合法入口恒 ≥ `0x52000000`）。

### ③ arch/riscv/crt0/crt0.S：app 的运行环境与返回
- **存内核现场**：`ra`/`sp` 存进 `.data` 的固定槽（不能借 `a0`，不能碰 `s0-s11`）；
- **换栈**：共享栈顶 `0x50400000`（避免与内核栈 `0x50500000` 交叠）；
- **清 BSS**：用 `sb` **逐字节**（app 的 `__bss_start` 非 8 对齐，用 `sd` 会越界）；
- **谢幕**：恢复 `sp`/`ra` 后 `jr ra` 回到内核。

### ④ init/main.c：点菜台
- `read_taskid()`：只认 `'0'..'9'`，其余只回显；`-1` 跳过；
- 越界 → 报错并 `continue`，绝不跑飞；
- **跳转 app 的 inline asm**：`la ra,1f` + `jalr a0,%0` + `1:`，
  把返回地址显式送进 `ra`（双保险写法，语义与编译器隐式生成等价）。

### ⑤ include/os/task.h：布局常量
- `KERNEL_FIXED_SECTORS` / `APP_FIXED_SECTORS` / `IMG_APP_NUM_LOC`（须与 createimage.c 一致）。

## 4. 任务 4：紧凑镜像 + AppInfo 名册 + 按名加载

**我做了什么（一句话）**：把镜像从"固定扇区分配"改成"按实际大小紧凑排列"；
在镜像里立一份"名册"（AppInfo）记录每个 app 的名字/位置/大小/入口；让内核按**名字**加载程序。

**六块改动**：

### ① createimage.c
- 定义 `task_info_t`（name[16] + start_sector + sector_num + vaddr_entry = 28 字节）；
- 内核与各 app **按实际大小紧凑排列**，只给 bootblock 补到扇区边界；
- 名册写进扇区 `1+K`（K = 内核实际扇区数），**未用槽清零**、**名字超长报错**；

## 5. 任务 5：双镜像 + 运行时动态加载 + list 命令

**我做了什么（一句话）**：把内核和应用拆成两个镜像文件，启动只读内核镜像；
应用数据在"要点名运行它"的那一刻才从卡上读；并加一个 `list` 命令显示应用信息。

**七块改动**：
- ① `createimage.c`：产出 `build/kernel.img`（bootblock+内核+AppInfo）与 `build/apps.img`（纯 app）；
  AppInfo 的 `start_sector` 改为 **apps.img 内的相对扇区号**（两文件解耦）；
- ② `Makefile`：`cat kernel.img apps.img > image` 拼接（等价于"分别写入 SD 卡连续扇区"），

- ③ `bootblock.S`：增传 `a2 = apps 区基址 = 1+K+A`；
- ④ `head.S`：保存 `a2`；
- ⑤ `task.h`：`boot_apps_base` 声明；
- ⑥ `loader.c`：`bios_sd_read(vaddr_entry, sector_num, boot_apps_base + start_sector)`；
