# 04 任务2：加载内核、建立 C 环境、键盘回显

> **读完你能回答的 3 个问题**：① 内核扇区数 K 从哪里读出来、bootblock 怎么用它？
> ② head.S 为什么必须清 BSS、为什么用 `__bss_start` 符号而不是硬编码地址？
> ③ `bios_getchar` 返回 -1 时不处理会怎样（为什么乱码）？

> 本小节按 **Task 2 形态**讲述三件事：①bootblock 把内核从 SD 卡读进内存；②head.S
> 清 BSS、设栈、跳 main；③main 键盘回显。后续任务在此基础上扩充。

## 1. 全景

```
bootblock（0x50200000）
   │ lh 读 0x502001fc → K（内核扇区数）
   │ 循环：bios_sd_read(目标内存, 1, 扇区号)  扇区号 1..K
   ▼ jal 0x50201000
head.S :: _start
   │ csrw sie/sip = 0（关中断）
   │ 清 BSS：__bss_start .. __BSS_END__ 写 0
   │ sp = 0x50500000（内核栈，向下生长）
   │ jal main
   ▼
main.c :: main
   │ bss_check()：验证 BSS 是 0
   │ init_jmptab()：填 BIOS 跳转表 0x51ffff00
   │ 打印 "Hello OS!" 与 "bss check: t version: 2"
   ▼
   回显循环：bios_getchar() → 若 == -1 跳过 → 否则 bios_putchar(该字符)
```

## 2. bootblock 的内核加载循环（Task 2 追加段）

```asm
	li    t3, os_size_loc       // t3 = 0x502001fc（扇区数字段的地址）
	lh    t2, 0(t3)             // t2 = 内核占用的扇区数 K（有符号半字加载）
	li    t0, 1                 // t0 = 本次要读的 SD 扇区号（第 1 扇区 = 内核开头）
	li    t1, kernel            // t1 = 目标内存地址 = 0x50201000
read_loop:
	beqz  t2, read_done         // 若 K==0 就跳过（防御）
	move  a0, t1                // a0 = 读到哪
	li    a1, 1                 // a1 = 一次读 1 个扇区
	move  a2, t0                // a2 = 从哪个扇区读
	li    a7, BIOS_SDREAD       // a7 = 11
	call  bios_func_entry
	addi  t1, t1, 512           // 目标地址 += 512
	addi  t0, t0, 1             // 扇区号 +1
	addi  t2, t2, -1            // 剩余扇区 -1
	j     read_loop
read_done:
	jal   kernel                // 跳转到内核入口
```

逐行要点：

| 行 | 做什么 / 为什么 | 删掉会怎样 |
|---|---|---|
| `lh t2, 0(t3)` | **半字**读 0x1fc 的 2 字节（小端）。K 由 createimage 写入，这是"内核多大"的唯一信息源 | t2 脏值：读 0 个/错乱个扇区 |
| 为什么先 `li t3` | `lh` 的地址必须是"寄存器+偏移"，GAS 不会替你把绝对地址物化进访存指令 | —（`lh t2,0(绝对地址)` 直接编译不过） |
| 为什么逐扇区读 | 与任务书一致、不绑定 K、与 Task 3 loader 形态统一；代价是 K 次 ecall | 若一次读 K 个也能成，但代码要换写法 |
| `addi t1,t1,512` | 内核在内存里连续，512 一扇区递增 | 一直写第一个扇区位置，内核被覆写 |
| `jal kernel` | 带链接跳转，ra = 下一条（=stop） | 用 `j` 则没有返回点，但内核不回 bootblock，影响不大 |

实测反汇编关键片段（Task 2）：

```
50200016: lui t3,0x50200; addiw t3,t3,508   # t3=0x502001fc
5020001e: lh  t2,0(t3)                        # t2 = 4（当时内核 4 扇区）
50200024: lui t1,0x50201                       # t1 = 0x50201000
50200028: beqz t2,50200046 <read_done>
...
50200046: jal 50201000 <kernel>
```

> **Task 3 后变更**：createimage 改成固定扇区，但 bootblock 这段"从 0x1fc 读 K、
> 循环读 1..K"**一字未改**随任何后续任务沿用；Task 4/5 只在 `read_done` 之后加了
> "传 a0/a1/a2"，没有动读扇区的循环本身。

## 3. head.S（内核入口，Task 2 形态）

```asm
.section ".entry_function","ax"
ENTRY(_start)
  csrw CSR_SIE, zero           // 关中断（还没配好中断，先全关）
  csrw CSR_SIP, zero
  la    t0, __bss_start        // 取 BSS 起止（链接脚本给的绝对符号，不硬编码）
  la    t1, __BSS_END__
clear_loop:
  bge   t0, t1, clear_done
  sd    zero, 0(t0)            // 一次写 8 字节 0
  addi  t0, t0, 8
  j     clear_loop
clear_done:
  li    sp, KERNEL_STACK       // 0x50500000
  call  main
loop:
  wfi
  j loop
END(_start)
```

| 要点 | 说明 |
|---|---|
| 为什么清 BSS | 镜像里只有 `p_filesz`（已初始化数据），BSS 不在镜像里；main 的 bss_check 会检查 `buf[50]` 是否为 0 |
| 为什么用符号而不是地址 | `__bss_start/__BSS_END__` 由链接脚本在任何布局下自动给出；硬编码地址=布局一变就错 |
| 为什么 `sd`（8 字节） | 比 `sb` 快。**依赖 `__bss_start` 8 字节对齐**——当前 0x50201bd8 通过；每次布局变化要复查，不满足就改 `sb`（crt0 侧一直用 `sb`，因为 app 的 bss 起点常非 8 对齐） |
| `sp=0x50500000` | 官方指定内核栈顶，16 字节对齐，向下生长；高于内核代码/跳转表，不与 app 区冲突 |
| `call main` | ra = 下一个 `loop:`；main 回来后进入 wfi 兜底 |

> **Task 4 后变更**：`clear_done` 后、`li sp` 前追加"把 bootblock 传来的 a0/a1/a2
> 存进 `boot_appinfo_sector/boot_appnum/boot_apps_base`"（且必须**在清完 BSS 之后**
> 存，否则全局量被清掉）。

## 4. main.c（Task 2 形态的核心：回显循环）

```c
    while (1)
    {
        int ch = bios_getchar();   // 无输入时返回 **-1**（U-Boot 的 cgetc 约定）

        if (ch == -1)
            continue;              // 关键：不跳过会把 -1(0xFF) 当字符打出去 = 乱码

        bios_putchar(ch);          // 回显
    }
```

| 问题 | 答案 |
|---|---|
| 为什么会有 -1？ | `bios_getchar` → U-Boot `__serial_cgetc()`：串口没数据时 getc 返回 -EAGAIN，包装成 -1 返回（出处：Phase 0 §5，与 u-boot 源码交叉验证） |
| 不跳过会怎样 | `bios_putchar(0xFFFFFFFF)` 打出整个 0xFF 字节 → 屏幕上全是乱码 |
| 回显 = 什么 | 终端输入"hello\n"，驱动脚本能断言日志里出现 "hello"（终端本身不回显，我们代码回显） |
