## 1. 我们在做什么

单机、单核引导一个"能自己运行小程序"的操作系统雏形。从通读仓库（Phase 0）到五步
实现，最终在 QEMU 上：开机 → 引导块打印 → 加载内核 → 内核交互地**按名字**运行
用户程序（2048 / auipc / bss / data），并能在运行时才从"SD 卡"读入用户程序（教学上
模拟一个"有很多文件的文件系统"）。

一句话：**把汇编、链接、内存布局、设备读取这些"底层发生了什么"逐一亲手做一遍**。

## 2. 启动链路全景（ASCII）

```
上电（QEMU：make run，-kernel ~/OSLab-RISC-V/u-boot/u-boot，-drive file=build/image）
   │
   ▼
U-Boot（即"BIOS/BBL"，占据内存 0x50000000–0x501fffff）
   ├─ autoboot 末尾自动执行：virtio read 50200000 0 2
   │     ← 把镜像【前 2 个扇区】预读进内存 0x50200000–0x502003ff
   │       （所以 bootblock 代码、以及镜像信息字段 0x1f8/0x1fc/0x1fe 此刻已在内存）
   ├─ 打印 "Hit any key to stop autoboot: 0" 与 "=> " 提示符
   └─ 我们在终端输入 loadboot
        → loadboot 只做一件事：mret 到 0x50200000（切换到 S 态、PMP 权限全开）
   │
   ▼
bootblock（编译期链接到 0x50200000；代码必须 ≤ 512 字节；没有 C 栈，纯汇编）
   ① bios_putstr 打印 "It's Dreamerhyh's bootloader..."
   ② lh 指令读内存 0x502001fc ← 内核占用的扇区数 K（createimage 写的）
   ③ 循环调用 bios_sd_read，把 SD 卡扇区 1..K 读到内存 0x50201000 起
   ④ 传参 a0/a1/a2（镜像布局参数），jal 跳转到 0x50201000
   │
   ▼
内核（编译期链接到 0x50201000；head.S 入口）
   head.S：清 BSS（__bss_start → __BSS_END__）→ 保存 boot 参数到全局量 → sp=0x50500000 → 跳 main
   main.c：
     ① bss_check()：验证 BSS 真的被清成 0
     ② init_jmptab()：把 BIOS 函数指针填进跳转表 0x51ffff00
     ③ init_task_info()：读 AppInfo 区，得到每个用户程序的名字/入口等信息
     ④ 打印 "Available tasks: ..."
     ⑤ 死循环：读一行名字 → 匹配 → bios_sd_read 读入该 app → 跳过去执行
        → app 里的 crt0 清理现场并准备 C 环境 → app. main 跑完 → 交回内核 → 回到 ⑤
   │
   ▼
用户程序（链接到 0x52000000 + i*0x10000，每个 app 占 64KB 窗口）
   如 auipc 打印 "testpc = 0x…"、bss 检查自身 BSS、data 校验数据数组、2048 小游戏
```

## 3. 五任务定位

| 任务 | 你要解决的问题 | 主要产出 | 对应 commit |
|---|---|---|---|
| Phase 0 | 这个仓库里到底有什么？ | 勘察报告 | `686458c`(随任务1) |
| 任务 1 | 引导块怎么"说话"？ | bootblock 调 BIOS 打印 | `686458c` |
| 任务 2 | 引导块怎么把内核"搬"进内存并交给 C？ | bootblock 读内核 + head.S 清 BSS/建栈 + main 回显 | `0c2d8e0` |
| 任务 3 | 能不能自己造镜像？能不能跑多个程序？ | 自建 createimage + taskid 加载 + crt0 | `29cb939` |
| 任务 4 | 镜像别浪费空间，按名字找人 | 紧凑排列 + AppInfo + 按名加载 | `d6f2c5f` |
| 任务 5 | 内核和应用分开，用谁读谁 | 双镜像 + 运行时动态加载 + list 命令 | `d5d0d19` |

> 演进提醒：bootblock.S / createimage.c / main.c / loader.c 在任务间都会"长大"。
> 03–07 各小节**按该任务当时的形态**讲解，小节末注明"Task N 后变更为……"，与
> git 历史一致。你看到的最新代码是五任务叠加后的最终形态。

## 4. 关键地址速查（先混个眼熟，08 详解）

| 地址 | 干什么的 |
|---|---|
| `0x50150000` | BIOS 统一入口：一条 ecall + ret（功能号放 a7，参数放 a0…） |
| `0x50200000` | bootblock 加载/运行地址 |
| `0x502001f8 / fc / fe` | 镜像信息字段：app 数 / 内核扇区数 / 签名 `55 aa` |
| `0x50201000` | 内核入口（head.S 的 _start） |
| `0x50400000` | **app 共享栈顶**（所有用户程序共用一个栈，向下生长） |
| `0x50500000` | **内核栈顶**（KERNEL_STACK，向下生长） |
| `0x51ffff00` | 内核 BIOS 跳转表（KERNEL_JMPTAB_BASE） |
| `0x52000000 + i*0x10000` | 第 i 个用户程序的入口/窗口 |

（`.scratch/verify.sh`，公开但未入库），给出"注入序列 + 断言 + QEMU 日志"三层证据。
