# 08 内存与镜像布局图解

> 三张 ASCII 图对应三个任务版本的内存/镜像布局（数值均取自各任务实测日志），再补
> 信息字段与内存映射总表。要点：**镜像信息字段随任务演进但语义不变**（0x1f8=app 数 /
> 0x1fc=内核扇区数 / 0x1fe=签名 55aa），AppInfo 槽位是 `task_info_t` 数组。

## 0. 信息字段速记（始终成立）

```
第 0 扇区（bootblock 自己的扇区）尾部，镜像偏移：
  0x1f8  [2B LE]  app 数目            ← bootblock lh 读取（Task4 起传 a1）
  0x1fc  [2B LE]  内核扇区数 K（实际值）← bootblock lh 读取，官方推荐约定
  0x1fe  [2B LE]  签名 55 aa           ← 官方引导签名，不许覆盖
```

> 历史更正：教学计划早稿曾写"app 数在 0x1fe"，**这是错的**——0x1fe 是签名位置，
> 两者冲突。最终以 **0x1f8** 为准（用户裁决，Phase 0 报告勘误 4）。

## 1. Task 3 —— 固定扇区版（`make image` 实测：93 扇区 = 47616 字节）

```
扇区/字节偏移               内容
┌─────────────────────────┬──────────────────────────────────────────────┐
│ 0     (0x000)           │ bootblock（1 扇区，代码 ≤512B）               │
│ 1..32                   │ 内核【分配 32 扇区，实际仅 4】                │
│ 33..47                  │ 2048  （分配 15 扇区，实际 10）               │
│ 48..62                  │ auipc （分配 15 扇区，实际  2）               │
│ 63..77                  │ bss   （分配 15 扇区，实际  1）               │
│ 78..92                  │ data  （分配 15 扇区，实际  9）               │
└─────────────────────────┴──────────────────────────────────────────────┘
   里侧细节（第 0 扇区尾部）：
   0x1f8 04 00 │ 0x1fc 04 00 │ 0x1fe 55 aa      （app数=4，内核扇区=4，签名）
   loader: block = 1+32+taskid*15；读到 0x52000000+taskid*0x10000
   实际>分配 → createimage 打印对照表并 error() 退出
```

> Task 3 是"分配值"思维：固定槽位、简单、浪费；内核当时实际仅 4 扇区，却被安排在
> 32 扇区的区段里。

## 2. Task 4 —— 紧凑版（实测：29 扇区 = 14848 字节）

```
扇区                   内容
┌───────────────────────────────────────────────────────────────┐
│ 0                    bootblock（1 扇区）                        │
│ 1..5                内核（K=5，0x1fc 写 5）                     │
│ 6                   AppInfo（A=1：16×28=448B ≤ 512B）           │
│ 7..16               2048（10 扇区）                             │
│ 17..18              auipc（2 扇区）                             │
│ 19                  bss（1 扇区）                               │
│ 20..28              data（9 扇区）                              │
└───────────────────────────────────────────────────────────────┘
   AppInfo（扇区 6）槽位（task_info_t = 28B，16 槽，未用清零）：
   ┌────────────────┬───────────┬───────────┬───────────────┐
   │ name[16]       │start_sector│sector_num │ vaddr_entry   │
   │ "2048"       → │      7     │    10     │  0x52000000   │
   │ "auipc"      → │     17     │     2     │  0x52010000   │
   │ "bss"       →  │     19     │     1     │  0x52020000   │
   │ "data"      →  │     20     │     9     │  0x52030000   │
   │ ...余 12 槽全 0                                            │
   └────────────────┴───────────┴───────────┴───────────────┘
   注：Task 4 这里 start_sector 还是 SD 绝对扇区
```

## 3. Task 5 —— 双镜像版（实测：kernel.img 8 扇区 + apps.img 22 扇区 = image 30 扇区）

```
kernel.img（SD 扇区 0..7）            apps.img（SD 扇区 8..29）
┌──────────────────────────────┐     ┌───────────────────────────────┐
│ 0  bootblock（130B，1 扇区）   │     │ 8..17   2048  (rel 0..9)     │
│ 1..6 内核（K=6）              │     │ 18..19  auipc (rel 10..11)   │
│ 7   AppInfo（A=1）            │     │ 20      bss   (rel 12)      │
│     ├ name="2048" start=0…    │     │ 21..29  data  (rel 13..21)  │
│     ├ name="auipc" start=10…  │     └───────────────────────────────┘
│     ├ name="bss"   start=12…  │      start_sector = apps.img 内【相对扇区】
│     └ name="data"  start=13…  │      加载：bios_sd_read(vaddr, num, base + rel)
│         （16 槽，未用清零）     │      base = 1+K+A = 8
└──────────────────────────────┘
   Makefile: cat kernel.img apps.img > image（连续字节流 ≈ 两文件写入 SD 卡连续扇区）
   0x1f8=04 / 0x1fc=06 / 0x1fe=55aa（仍写在 kernel.img 第 0 扇区）
```

任务 5 三传参（bootblock → 内核）：`a0 = 1+K(=7)`、`a1 = app数(4)`、`a2 = 1+K+A(=8)`。

## 4. 内存映射总表（最终态）

```
0x50000000 ┬ U-Boot（BIOS/BBL）
0x50150000 │   BIOS 入口：ecall + ret（功能号 a7，参数 a0…）
0x501fffff ┘
0x50200000 ┬ bootblock（镜像扇区 0；由 loadboot 跳入）
           │   [0x502001f8/0x1fc/0x1fe] 信息字段
0x50201000 ┬ 内核入口 head.S::_start
           │   （内核代码与 BSS 结束于 ~0x502021c0）
0x50400000 ┬ app 共享栈顶（所有 app 共用，向下生长）
           │   （0x50400000–0x50500000 为内核栈独享带）
0x50500000 ┴ 内核栈顶 KERNEL_STACK（向下生长）
0x51ffff00 ─ 内核 BIOS 跳转表（KERNEL_JMPTAB_BASE，5 槽×8）
0x52000000 ├ app0 窗口（2048）
0x52010000 ├ app1 窗口（auipc）
0x52020000 ├ app2 窗口（bss）
0x52030000 └ app3 窗口（data）
```

## 5. 三版对照（数值都是实测）

| 版本 | 内核扇区数 | app 槽位 | 总镜像扇区 | start_sector 语义 |
|---|---|---|---|---|
| Task 3 | 4（分配 32） | 每 app 固定 15 | 93 | **SD 绝对扇区**（公式算出） |
| Task 4 | 5 | 紧凑 | 29 | SD 绝对扇区（AppInfo 字段） |
| Task 5 | 6 | 紧凑（kernel/apps 拆分） | 30（kernel 8 + apps 22） | **apps.img 相对扇区** + base=1+K+A |

> 内核从 4→5→6 扇区，源于 main.c/bootstrap 不断加入功能（readline、list 等）；
> 因此验证脚本**不硬编码**扇区数，一律用 createimage 打印值与文件实际大小互证。
