# 06 任务4：紧凑镜像 + AppInfo + 按名加载

> 本小节按 **Task 4 形态**讲述：①createimage 取消固定扇区、紧凑排列、写 AppInfo；
> ②bootblock 传参替代内核直读信息区；③init_task_info 用 512B 缓冲中转；④按名匹配的
> loader 与 readline。Task 5 再演进为双镜像（07）。

## 1. 全景

```
createimage（Task 4 形态，单文件 image 仍成立）
   │ 紧凑：bootblock(1) + 内核(K=NBYTES2SEC(p_filesz)) + AppInfo(1扇区) + 各 app 紧贴
   │ 写 0x1f8=app数 / 0x1fc=K(实际) / 0x1fe=55aa
   │ 打印布局核算表（app1 起始扇区 = 1+K+A，无固定空泡）
   ▼ image
bootblock：读内核(1..K) → a0=1+K(AppInfo) / a1=lh(0x1f8)(app数) → jal kernel
   ▼
head.S：清 BSS → sd a0→boot_appinfo_sector / a1→boot_appnum → sp → main
   ▼
init_task_info()：读 AppInfo(1+K) 到 512B 对齐缓冲 → memcpy 进 tasks[]
   ▼ 任务名列表 + 提示
readline(name) → load_task_img(name)：遍历 tasks[]，strcmp(name)
    → bios_sd_read(tasks[i].vaddr_entry, sector_num, start_sector)   ← 绝对扇区（Task 4）
   → 跳 entry
```

## 2. createimage 的 compact 布局（Task 4 形态要点）

```
扇区 0          bootblock
扇区 1 .. K     内核（K = NBYTES2SEC(p_filesz)），0x1fc 记录实际 K
扇区 K+1        AppInfo 区（A=1：16×28 = 448 ≤ 512）
扇区 K+2 ..     各 app 按实际大小紧凑排列，app i 紧贴 app i-1
```

- `task_info_t{name[16], start_sector, sector_num, vaddr_entry}` = 28 字节；
  AppInfo 里 `start_sector`/`sector_num` **是 SD 绝对扇区**（Task 4 形态）；未用槽清零，
  内核靠 `name[0]=='\0'` 识别空槽。
- 名字超过 `TASK_NAME_LEN` → `error()` 退出，绝不截断。
- 布局自检：写完按公式核算总扇区，与文件实际大小必须一致。
- **无固定空泡**：`app1 起始扇区 = 1+K+A`（例：内核 5→AppInfo=1→2048 从扇区 7 开始）。

Task 4 实测布局表节选（`make image`）：

```
0x50201000: main  sec  1 ..  5    (2416 bytes, 5 sectors)
-APPINFO--- appinfo sec 6 .. 6    (448 bytes, 1 sectors)
0x52000000: 2048  sec  7 .. 16    (5032 bytes, 10 sectors)
...
[layout] total sectors : 29 = 1 + 5 + 1 + 22
```

## 3. bootblock 传参（为什么不再让内核直接读 0x50200xxx）

Task 3 内核直读 `0x502001f8` 拿 app 数，依赖 U-Boot `virtio read 50200000 0 2` 预读
2 扇区的**副作用**——若只预读 1 扇区该读法立即失效。于是 Task 4 改为 bootblock 主动传参：

```asm
read_done:
	move  a0, t0               /* a0 = 1+K（循环结束 t0 恰好停在 1+K）*/
	li    t3, os_size_loc - 4  /* 0x502001f8 */
	lh    a1, 0(t3)            /* a1 = app 数 */
	jal   kernel
```

head.S 在**清完 BSS 之后**存参（两个全局量在 .bss，先清再存）：

```asm
	la t2, boot_appinfo_sector;  sd a0, 0(t2)
	la t3, boot_appnum;          sd a1, 0(t3)
```

> `init_task_num()`（Task 3 直读法）在 Task 4 **删除**；内核从此不读 0x50200xxx。

## 4. init_task_info：为什么要 512B 对齐缓冲中转（Task 4 最重要的隐患）

```c
static uint8_t appinfo_buf[SECTOR_SIZE] __attribute__((aligned(SECTOR_SIZE)));

task_num = (int)boot_appnum;
bios_sd_read((unsigned)(unsigned long)appinfo_buf, APPINFO_SECTORS,
             (unsigned)boot_appinfo_sector);          // 读 1 个扇区=512B 到缓冲
memcpy((void *)tasks, (const void *)appinfo_buf,
       (size_t)task_num * sizeof(task_info_t));        // 只拷 task_num×28 字节
```

**为什么不能整扇区直读 `tasks[]`**：`tasks[TASK_MAXNUM]` = 16×28 = **448 字节**，
但 `bios_sd_read` 一次读 512 字节——直接读进 tasks[] 会**越界覆写其后 64 字节的 .bss**
（把 `task_num`、`boot_apps_base` 等变量冲掉）。缓冲 + memcpy 只拷真数据。
这是 Task 4 反复强调的防线，09 会用真实调试案例展开。

## 5. 按名加载：readline + load_task_img

**readline 的语义**（关键决策）：
- 每行以 `\r` 或 `\n` 终止（双终止符，兼容终端/脚本两种回车）；`\r\n` 的另一半会以
  空行被瞬间消费，调用方忽略空行；
- 支持 `\b`(BS)/`0x7F`(DEL) 退格，回显"退格+空格+退格"擦除屏幕字符；
- 名字上限 `TASK_NAME_LEN-1` = 15；**超长则整行作废**返回 0；
- 空行返回 0 → 打印 `Error: invalid input!` 回到输入循环。

```c
uint64_t load_task_img(const char *taskname)
{
    for (int i = 0; i < TASK_MAXNUM; ++i)
    {
        if (tasks[i].name[0] == '\0') continue;        // 未用槽
        if (strcmp(tasks[i].name, taskname) == 0)      // 按名匹配
        {
            if (bios_sd_read(tasks[i].vaddr_entry, tasks[i].sector_num,
                             tasks[i].start_sector) != 0)   // Task 4：绝对扇区
                return 0;
            return (uint64_t)tasks[i].vaddr_entry;
        }
    }
    return 0;
}
```

> 迭代遍历 `TASK_MAXNUM` 而非 `task_num`：未用槽已被 createimage 清零，按 `name[0]`
> 跳过即可，不需要额外知道数量。

## 6. -O2 的如实说明

- `Makefile` 的 `CFLAGS = -O2 …` 是 **start-code 自带的**，bootblock/内核/app 从任务 1
  起就按 -O2 编译；
- 因此任务书"修改 Makefile，给内核和用户程序加 -O2"在现状下**没有动作可做**，
  Task 4 系"确认生效"；也没有一个"Task 3 非 -O2 内核"可做体积对比——如实报告，
  不伪造"对比缩小"。
