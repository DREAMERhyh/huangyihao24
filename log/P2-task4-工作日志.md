## 任务书要求（§5.8，印刷页 20）

**实验要求**：
1. 掌握 RISC-V 中断处理流程；
2. 实现定时器中断处理逻辑，并基于定时器中断实现**轮转式抢占**；
3. 运行给定测试任务（**要求注释掉所有 `sys_yield`**），输出与任务3 一致的结果。

**实验步骤**：完善 `trap.S` 的 `setup_exception`（打开全局中断使能）→ 初始化
`irq_table` → 实现 `handle_irq_timer`（重设 timer、重新调度）→ `main.c` 里武装第一次
时钟、把 `while(1)` 里的 `do_scheduler` 换成 `enable_preempt` → 复跑全部测试。

**注意事项 1**："如何正确地开始一个任务的第一次调度，在抢占调度模式下和非抢占
调度模式下是不同的"；**要点解读**：栈指针一旦设置/保存/恢复错，会带来难以调试的错误。

## 关键设计决策

1. **抢占的触发链**：`sstatus.SIE=1` + `sie.STIE=1` → 时钟中断 →
   `exception_handler_entry`（SAVE_CONTEXT）→ `interrupt_helper` → `irq_table[5]` →
   `handle_irq_timer` → `do_scheduler` → `switch_to` → …下一个任务被切换上场。
2. **第一次调度由时钟中断发起**（注意事项 1 的答案）：非抢占是 main 主动调
   `do_scheduler`；抢占模式下 main 打开中断后空转（`wfi`），第一个时间片到点时
   由时钟中断把第一个任务送上场。**因此内核自己（pid0）也必须有合法的 `sscratch`**——
   内核被打断时 SAVE_CONTEXT 需要一个内核栈顶，否则陷阱帧会写到地址 0。
3. **下一次 timer 的落点**：每次 `do_scheduler` 换人时
   `bios_set_timer(now + 时间片)`——时间片因此直接就是"被抢占的间隔"
   （任务5 把它固定成 `SLICE_LEN = TIMER_INTERVAL/4`，见 task5 日志）。
4. **idle 用 `wfi`**：没任务可跑时内核在 `wfi` 里睡等下一次时钟中断。

## 踩坑与修复：抢占模式下"先被选中的任务稳定快 20%"

**现象**：时钟中断驱动、测试程序全部注释 `sys_yield` 时，两个**完全相同**的测试
程序产出稳定差 17~21%，且总是"先被选中的那个快"（交换选择顺序后，快的仍跟
pid 走、不跟程序走）。

**定位过程**（每步都做对照实验）：
1. 关掉 `sys_reflush` → 偏差照旧（与刷屏无关）；
2. 数被调度次数/CPU 占比/片长 → 185/185/184、35.9%/36.7%、188k/200k，全相等
   （**不是"少给时间"**）；
3. 内核里逐事件计数（每完成一次迭代，各任务让内核干了多少活）→ 两边完全一样
   （每格活相同，问题必在"时间"上）；
4. 让**同一个程序跑两份**（同代码同窗口，只有 PCB/队列位置不同）→ 偏差仍 26.7%
   （纯粹是位置效应）；
5. 把 `main` 空闲里的 `wfi` 临时换成忙等 → 偏差掉到几个百分点（主要放大器找到）；
6. 加 `-icount shift=3,sleep=off`（虚拟时钟 = 指令数）→ 偏差彻底消失（Δ0.006%，
   未修复的代码也 Δ≤0.2%）。

**根因**（表述经独立复核修正）：guest 的 `rdtime` 是**宿主墙钟、不是执行量**，而
QEMU 在"1 核 + 高负载"宿主上会被反复抢占；`wfi` 是 guest 里唯一主动把宿主 CPU
让出去的地方，一睡一醒会把宿主调度器相位与 guest 轮转**对齐**，于是误差从"随机"
变成"按轮转槽位稳定偏向"。准确说法是 **"QEMU 时间基准 + 宿主超载"**，不是
"wfi 的 bug"。

**修复**（`c6057e4`）：pid0 退出轮转，只在"就绪队列为空"时上场兜底（并顺手把
pid0 的时间戳对齐，免得把"开机以来的全部 tick"记到它账上）。效果：print1/print2
从 17~21% 降到 0.4~5%（多次实测），`-icount` 下 Δ0.006%。
**勘误**：此前 commit message 写"产出量提升约 3 倍"是错的（对比了不同宿主负载的
数据）；两任务产出总量基本不变，变化的是**分配**（原来 1/3 时间片被怠速白占）。

## 验收辅助：Ctrl+C 热重启（`34ae799`）

测试程序是死循环，调度开始后内核不再读键盘，换一组任务只能退出 QEMU 重来。
`handle_irq_timer` 开头顺手看一眼键盘（每个节拍一次 M 模式调用），按 Ctrl+C
则 `restart_kernel()`：断开两条队列、把 bootblock 传来的引导参数重新放进
a0/a1/a2、`csrw sie, zero`、跳回 `_start`——一秒回到选任务提示符。
正常验收不会按到它；不想要的话删掉 irq.c 里那三行即可。
